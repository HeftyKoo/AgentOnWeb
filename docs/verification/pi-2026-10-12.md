# Pi support verification - 2026-10-12

Implemented on `codex/pi-support`, following the Claude Code adapter's authenticated per-terminal event transport and runtime-neutral `AgentSession` contract.

## Behavior

- `aow setup` installs the Pi extension; `aow pi-extension install|uninstall` manages it separately.
- The marked loader lives at `PI_CODING_AGENT_DIR/extensions/agentonweb.ts`, defaulting to `~/.pi/agent/extensions/agentonweb.ts`. Tilde paths match Pi's configuration behavior. Settings, models and other extensions are preserved; conflicting unmarked files are refused.
- The shipped `lib/pi-extension.js` observes Pi 1.1+ lifecycle and UI prompt events, preserving event order and failing open on transport errors. It registers no handlers outside host-owned terminals and never changes prompts, tools, context or permission decisions.
- Working, input/confirmation, final completion, interruption, provider error and session shutdown normalize into existing browser presentation. `agent_settled` is the completion boundary; intermediate `agent_end` events do not notify.
- Terminal close removes Pi sessions; reconnect restores the latest snapshot. Codex, Claude Code and Pi session identities remain independent.

## Delivery boundary

These checks establish local source, package and Chrome 153 workflow readiness. They do not commit, push, merge, publish to npm/browser stores, change the user's Pi configuration or restart the installed terminal service. Loading the integration requires the updated host and `aow pi-extension install` (or `aow setup`), then starting Pi or running `/reload`.

Pi 1.1+ is required. Disabling extensions or dropping the inherited event environment prevents reporting. Force-killing Pi without a shutdown event can leave its snapshot until the host terminal closes.
